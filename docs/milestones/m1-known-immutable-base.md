# Known immutable common-base readback

Approved ADR-0009 continuation; GA-DOM-006 and GA-DATA-001/002/003/004/010/011.
This component verifies an explicitly known retained common publication before
source comparison. It does not discover another client's files or treat a missing
reference as an empty remote namespace.

Scope construction requires the retained publication's complete working and
immutable receipts and its published head acknowledgement. The frozen capture's
common revision/source hash, expected generation/tag, binding, account, head,
working/metadata folders and marker must agree with that publication. The exact
revision folder remains under the selected Template's History. Aliases against
working/source/namespace/head identities fail. Existing strict source/compiler
checks run before a token-bearing batch is constructed.

The production socket profile exposes only GETs for those exact folder, manifest
and source identities. Listing, unknown objects, folder media and all mutations
fail before the budget or socket. The existing strict immutable reader verifies
account, owner-only access, parents, markers, names, MIME and bracketed strong
tags, with original metadata/content retained before interpretation. Each
received object404 is retained once, including namespace and media failures.
Missing immutable files cannot be recreated. Changed bytes/hash/size stop with
a conflict, preserving the observed bytes. The complete received manifest and
sources pass the existing compiler and canonical source/plan hash contracts.
Namespace verification runs again before returning the source.

The IO executor obtains marker authority from the current leased Room binding.
Before every reserved HTTP request it rechecks capture origin, frozen local/base
context, scope and retained publication files. Raw callbacks use the same leased
observation journal. Cancellation, expired ownership, budget or proof corruption
cannot return a verified source result; batches close on success/failure. Tokens
remain memory-only. The current remote head and working branch remain separate
observations: verifying an older common base cannot select a whole-version winner
or authorize a provider overwrite.

Local169 Android JVM/36 adapter JVM checks pass. Six new JVM cases cover acknowledged
base binding, exact readback/charges, absent/corrupt immutable objects, metadata/
account/ancestry/tag failures, raw retention, sink failure and the GET-only socket
boundary. Instrumentation compiles with two additional SQLite composition cases:
base readback/reopen, and corruption/budget/expiry rejection, preserving the prior
publication, original job and all twelve pre-sync tables. Actual current-head
execution across seven Android versions is still required. The two-file fake
records25 charged GETs and23 retained responses; this is offline evidence only.
