# M0 — Integrated technical feasibility prototype

## Scope and success question

Can an installable Android app and browser simulator reliably interpret and execute the *same nontrivial composite/pyramid workout* with deterministic time, pause and navigation behavior, and an evidence-based engine-sharing choice?

**M0 is a prototype, not the first daily-usable application.** Do not implement unrelated hosted auth, AI, billing, public sharing, PDF ingestion or production UI. Use synthetic training fixtures. Google Drive integration may be mocked if external authorization not yet approved; the provider-neutral interface/basic Drive integration remains in prototype scope but is not a live OAuth acceptance gate.

## Mandatory M0 acceptance

- [x] Android app installable on user's physical Android 12+ phone, launch/run a fixture.
- [x] Web simulator runs in a browser with identical fixture.
- [x] Realistic composite fixture alternates at individual-repetition level and contains at least one timed rest and differing per-set resistance metadata.
- [x] Both show phase progression and support pause, resume, step forward and step backward at basic scope; skipping never silently marks reps complete.
- [x] Virtual clock and tests establish identical expected phase order and deterministic 50,000ms scheduled timeline across engines. Wall-time and speech are *not* clock source.
- [x] Written analysis chooses shared KMP/JS vs separate engine on evidence; versioned contracts preserved either way.
- [x] CI runs tests and checks no unexpected tracked private fixtures or credentials.
- [x] Installation and browser instructions plus reproducible physical-device smoke-test notes supplied.

## Time records required in M0 tests

Scheduled phase time, observed monotonic execution time, pause duration, and unobserved gaps are separate. A virtual-clock test must show that pause does not consume scheduled phase time and that a step-over does not mark the skipped phase complete. A recovery test must show that an unobserved gap is not written as completed exercise. See `docs/architecture/execution.md`.

## Emulator scope

The M0 engine spike does not require an Android emulator matrix. M0 still requires the composite fixture, virtual-clock tests, deterministic traces, automated checks, and a physical-phone smoke test. Automated emulator testing across supported Android versions stays mandatory in later milestones (Decisions #48 and #54). Deferring it for the spike does not remove it.

## Not required as M0 acceptance gates

Actual Google Drive authorization/write; real AI, real PDF import, real journal export, completed production-grade background audio, historical migration, full Android session persistence, final hosting provider. They remain future acceptance gates per P0 requirements.

## Physical phone smoke scenario

Start fixture; let A1 prepare/hold complete, verify B1 next; pause during B1 and confirm remaining phase time stops, then resume; jump forward/backward and observe state/audit semantics; switch screen off and back on, record whether foreground behavior is correct; measure UI/clock drift with logs. Do not claim precise behavior when Android kills process; capture a safe recovery proposal.

## Acceptance review status — 2026-11-01

All eight mandatory evidence items above are satisfied at prototype scope. The
checked boxes record evidence, **not user approval to close M0**. The user reported
pause/resume, paused navigation, and short running/paused screen-off checks
passing on the verified APK. Codex subsequently captured a numerical foreground
baseline: running +8,727 ms, pause +5,647 ms with scheduled/observed frozen, and
resumed running +5,765 ms with pause frozen. All increments agree with their
sampled device-uptime intervals; capture/render latency prevents a precise drift
guarantee. See [device notes](m0-device-notes.md) and the sanitized
[timing log](m0-device-timing.json) for provenance and uncertainty.

The web production build and both dev-dependency audits now run in CI; current
audits report zero findings. Test suites total 73 reported tests, including the
shared full-event conformance harness. The repository hygiene gate checks obvious
private filenames/types; it is not a comprehensive credential scanner.

PR #2 remains open for explicit final review and approval. M0 is not the daily-use
release. Persistent recovery, long-duration platform/audio reliability, other OS
versions and approved quantitative performance thresholds remain later gates.
The existing non-failing Android Gradle plugin/compileSdk warning is carried debt.
