M1-01 partially supports GA-DOM-006 and GA-DATA-002. It validates the existing
draft explicit-order subset, including manual phases, without introducing new
schema or execution semantics. Optional sections and additional advanced patterns
remain required product behavior; the current schema does not represent them all.
A user-selected real workout PDF has been read with explicit per-operation
OpenAI-in-chat consent, outside Git and the synthetic Drive experiment. The owner resolved the execution ambiguities and approved the private preview
(including a 4-second repetition reset and fixed upper-bound targets); no executable real template has been
imported and no real workout recorded. M1 acceptance below remains open.

M1-02/03 are Python contract experiments, not a product engine/language decision.
Review never adopts a candidate or changes future defaults. A publishing
transaction must recheck the current revision after review; no persisted revision
hash, quarantine or conflict-branch format is introduced here. The memory adapter
tests compare-and-swap, stable create keys, operation replay and incremental change
pages. It is single-threaded and loses all state at exit; durable idempotency,
offline outbox, account grants and actual Drive semantics remain unproven.

**Minimum user-approved M1 scope:** real chosen workout template, Google Drive template/session synchronization, full Android workout recording (for a supported subset of advanced patterns), web review and interrupted-session recovery.

Implementation tasks: valid YAML template loader; storage-provider interface and Google Drive scope experiment; local durable Android log; explicit session-start snapshot; verified session ID/plan versions; resumable app state; outbox sync + error status; read-only web history; UI and privacy basics. Exercise family IDs and set occurrence IDs are designed correctly from start, even if only one fixture is executable initially. Editor and Google Sheets are later milestones.

Acceptance: complete a real workout on phone with internet temporarily disconnected; close/restart app and continue from checkpoint; sync immutable JSON history to *authorized* personal Drive; see same values on web; no duplicates after retry; no data loss when remote version changes. Record source template revision and event log. External services must be approved prior to any OAuth setup or cloud calls.

## Mandatory unfinished-session recovery

These criteria are mandatory for M1. They are not M0 acceptance gates. The 2026-11-01 Pixel 10a observation showed a clean restart after process termination and loss of the unfinished execution position. That limitation is accepted for M0 only.

M1 must:

- Write automatic workout checkpoints after execution transitions and user actions.
- Recover the last reliably recorded execution position.
- Show a resume/discard prompt after application restart.
- Preserve completed and partially completed performance records.
- Record no fabricated exercise progress during unobserved periods.
- Test process termination, restart, recovery, and subsequent synchronization.


**Season/Program foundation (new P0 features):** Establish provider-neutral stable IDs, schemas, optionally linked Program→Template membership and Season↔Program participation, version-resolution entry point and immutable optional session-start attribution. One active Season collection check; ungrouped Training Template execution MUST remain functional. The complete management UI is NOT an M1 gate, but is mandatory for first daily-use release. See `docs/architecture/seasons-programs-and-promotion.md`.
